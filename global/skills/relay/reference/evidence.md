# 설계 근거와 개선 제안

원자료는 `../research/`에 있다. `docs.md`(공식 문서 18개, [n] 번호), `papers.md`(논문 10편, P1~P10, PDF는 `research/papers/`), `oss.md`(오픈소스 10개). 모두 2026-11-08 확인.

## 1. 배치: 왜 전역 CLAUDE.md가 아니라 스킬인가

| 사실 | 근거 |
|---|---|
| CLAUDE.md는 매 세션 시작에 읽히고, @import한 파일도 함께 로드되어 비용이 줄지 않는다 | docs [1] memory: "Imports help you organize a long file but don't reduce its context cost" |
| 시작 시에는 스킬 이름과 설명만 들어간다. 설명은 1,536자에서 잘린다 | docs [2] skills, [8] context-window |
| 스킬 본문은 쓸 때만 로드되어 긴 참고 자료는 필요할 때까지 거의 비용이 없다 | docs [2] skills: "a skill's body loads only when it's used" |
| 로드된 본문은 그 세션 대화에 남는다(압축 때 스킬당 5,000토큰까지 재부착) | docs [2] |
| 슬래시 명령은 스킬과 같은 규칙을 따른다 | docs [3] |
| statusline은 로컬에서 돌고 API 토큰을 쓰지 않는다 | docs [7] statusline |
| 훅 출력은 일부 이벤트(UserPromptSubmit, SessionStart 등)만 컨텍스트에 들어간다. "통과 시 0토큰"은 추론 | docs [4] hooks |

→ 전역 CLAUDE.md에는 항상 알아야 할 몇 줄만, 나머지는 이 스킬과 `/handoff`·`/pickup` 명령에 둔다.

## 3. 개선 제안 (아직 적용 안 함, 사용자 승인 필요)

1. **상태 파일의 덧붙이기화**(P7): 결정·버린 것은 카드 로그에 덧붙이고, 상태 파일은 포인터만. 현재 카드 모드가 이미 이 구조에 가깝고, 글 모드의 `Decisions`가 매번 다시 쓰이는 점이 위험.
2. **완료 결과 3값**(spec-kit): `done_when` 결과를 verified / partial / failed로 기록.
3. **완료 조건 검토 단계**(P3): 카드 생성 시 `done_when`이 실패를 실제로 잡는지(먼저 실패를 확인) 검사. 검사기 관례에 이미 있음 → 카드 템플릿에도 명시.
4. **루트 AGENTS.md 진입점**(AGENTS.md 표준): 프로젝트 AGENTS.md에서 `.relay/HANDOFF-NEXT.md`를 가리켜 Codex·Antigravity도 같은 순서로 시작.
5. **Waiting·Next를 맨 앞에**(P4): 상태 파일 형식에서 Waiting을 META 바로 아래에 두는 현재 배치를 유지하고, 글 모드도 Next를 앞으로.
